# Adversarial Environment

## Overview

`AdversarialIoTEnv` is a Gymnasium environment where the RL agent learns to defend against attack sequences generated by the LSTM.

- **Hidden state**: Kill Chain stage is not observable.
- **Observation**: window of realized feature vectors from CICIoT2023.
- **Action space**: Force Continuum (5 discrete actions).

## Observation construction

Given a window size $k$ and $d$ features:

- Base observation: $k \times d$
- If `include_deltas=true`, concatenate per-step deltas (velocity)
- Flatten to 1D: shape $(k \cdot d \cdot m)$ where $m=2$ if deltas included

## Action space

| Action | ID | Cost |
|:------|---:|-----:|
| OBSERVE | 0 | 0.0 |
| LOG | 1 | 0.1 |
| THROTTLE | 2 | 0.3 |
| BLOCK | 3 | 0.5 |
| ISOLATE | 4 | 0.8 |

## Episode flow

1. **Reset**
   - Attack stage starts at BENIGN.
   - Observation window filled with BENIGN features.
2. **Step**
   - Action chosen by agent.
   - Reward computed against the *previous* stage.
   - Attack advances via LSTM unless defense ends episode.
   - New features sampled for the updated stage.
3. **Termination**
   - If attack reaches IMPACT, agent gets *one final action* at IMPACT (early return in `step`).
   - Episodes can truncate by `max_steps`.

## Attack advancement

Attack stage transitions are sampled by the LSTM based on recent history (last 5 stages).

## Hidden-state debugging

Info dictionary includes stage for evaluation/debugging:

- `attack_stage`
- `attack_stage_name`
- `attack_history`
