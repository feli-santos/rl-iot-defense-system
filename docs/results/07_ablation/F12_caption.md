**F12 — Security vs. availability "Pareto" (degenerate y-axis on `test_balanced`).** Each point is one (reward_config, p_defender_deescalation) cell from F9 + F10, plus the eight Phase-6 anchor policies, with x = availability cost (BLOCK + ISOLATE share of decisions) and y = security gain (1 − compromise rate). On `test_balanced` (`exclude_ood=True`), every one of the 32 candidates carries `compromise_rate = 1.0` exactly (every policy lets at least one IMPACT row land), so `security_gain ≡ 0` for all points and the figure is effectively a 1-D scatter on `availability_cost`. The "Pareto frontier" therefore degenerates to the single x-min point (`always_observe`). The dashed red curve highlights this trivial frontier; squares = Phase-6 anchors; circles = F9 reward-sweep cells; triangles = F10 aggressiveness cells. The figure's diagnostic message is **"the Phase-3 reward function does not produce a non-trivial 2-D operating-point trade-off on `test_balanced`"** — exactly the failure mode pre-registered as R7.3 in PLAN §6, and consistent with the F9 finding that no single coefficient perturbation moves PPO mean reward by ≥ 1σ. A 2-D figure with a non-trivial frontier would require a y-axis that varies under the Phase-3 reward formulation (e.g. `mitigated_impact_rate`, which **does** vary 0.153 → 0.900 in F9).
