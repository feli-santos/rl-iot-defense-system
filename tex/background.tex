\section{The Cyber Kill Chain as a Defender's Decision Frame}\label{sec:kill_chain}
The \textbf{Cyber Kill Chain} \cite{Hutchins2011,Naik2022} is a conceptual model that decomposes a sustained intrusion into a sequence of progressively more compromising stages. Originally formulated by industrial threat-intelligence practitioners~\cite{Hutchins2011} and refined by the academic community, it organizes adversary behavior as an ordered chain in which earlier stages prepare for the success of later stages and where defender opportunity costs grow monotonically with stage progression. Interrupting an attack at the beginning stages is far cheaper than at later stages.

Following the formulation adopted in this dissertation (and consistent with the IoTWarden recommended-action mapping \cite{Alam2024}), traffic on an IoT network is projected onto a five-stage kill chain:

\begin{enumerate}
    \item \textbf{\textsc{benign}} --- routine, non-malicious traffic. The defender's correct posture is observational.
    \item \textbf{\textsc{recon}} --- the adversary scans, fingerprints, or otherwise enumerates the network and its assets. The behavior is malicious but the network is not yet compromised; the defender's correct posture is to log and continue monitoring.
    \item \textbf{\textsc{access}} --- the adversary establishes an initial foothold (e.g.\ exploit-driven authentication bypass, brute-force, command injection). The defender should restrict the implicated traffic and prepare to escalate.
    \item \textbf{\textsc{maneuver}} --- the adversary performs lateral movement, privilege escalation, or other in-network manipulation to position for a final action. The defender should block.
    \item \textbf{\textsc{impact}} --- the adversary's terminal action: data exfiltration, denial-of-service, ransomware detonation. The defender's last opportunity to prevent loss is to isolate the affected segment.
\end{enumerate}

The kill chain is more than narrative scaffolding: it provides a discrete decision frame in which (i) the attacker's evolving state is summarized by a single ordered variable and (ii) the defender's action menu can be aligned to that variable through a recommended-action mapping (\textsc{benign}~$\to$~\textsc{observe}, \textsc{recon}~$\to$~\textsc{log}, \textsc{access}~$\to$~\textsc{restrict}, \textsc{maneuver}~$\to$~\textsc{block}, \textsc{impact}~$\to$~\textsc{isolate}). This alignment is what makes the rule-based recommended-action policy a meaningful upper bound on deployable performance (Section~\ref{sec:baselines}).

\section{Reinforcement Learning for Autonomous Systems}\label{sec:rl_concepts}
Reinforcement Learning (RL) is a computational paradigm focused on goal-directed learning from interaction. An intelligent agent learns to make optimal decisions not by being shown labeled examples, but by exploring an environment and discovering which sequences of actions yield the greatest cumulative reward \cite{Sutton2018}. The agent and the environment interact at a sequence of discrete time steps: at step $t$ the agent observes the state $s_t$ and selects an action $a \in A$, where $A$ is the set of available actions, and the environment responds with a new state $s_{t+1}$ and a scalar reward $r_{t+1}$. This closed loop, illustrated in Figure~\ref{fig:rl_agent_loop}, is the canonical RL setting. In certain cases, this learning process can be formalized through the mathematical framework of Markov Decision Processes (MDPs).

\subsection{Markov Decision Processes}\label{ssec:mdp}
An MDP provides a formal model for sequential decision-making under uncertainty. The core principle is the \textbf{Markov Property}, which asserts that the current state contains all information from the history necessary for optimal decisions, so previous states need not be consulted \cite{Sutton2018}. An MDP is defined as a five-tuple $(S, A, P, R, \gamma)$:
\begin{itemize}
    \item $\boldsymbol{S}$: A set of states, representing all possible configurations of the environment.
    \item $\boldsymbol{A}$: A set of actions available to the agent. For this work, $A$ is the five-action defender menu derived from the kill chain in Section~\ref{sec:kill_chain}: $A = \{\textsc{observe},\allowbreak \textsc{log},\allowbreak \textsc{restrict},\allowbreak \textsc{block},\allowbreak \textsc{isolate}\}$, ordered by escalating defensive force and operational disruption.
    \item $\boldsymbol{P}$: The state transition probability function, $P(s' \mid s, a) = \Pr(S_{t+1}=s' \mid S_t=s, A_t=a)$, defining the dynamics of the environment.
    \item $\boldsymbol{R}$: The reward function, $R(s, a, s')$, which provides the immediate numerical feedback for transitioning from $s$ to $s'$ via action $a$. The full as-built reward used in this dissertation is detailed in Section~\ref{sec:rl_environment}.
    \item $\boldsymbol{\gamma}$: The discount factor ($0 \leq \gamma \leq 1$), which prioritizes immediate rewards over future ones.
\end{itemize}
The agent's objective is to learn a \textbf{policy}, $\pi(a \mid s)$, which maps states to a probability distribution over actions, to maximize the expected discounted return.

\paragraph{From MDP to POMDP: the defender's perception gap.} In this dissertation the underlying simulator carries a \emph{latent} Markov state that includes the true kill-chain stage and the stage/action histories, and the defender does not observe this latent state directly: it receives only a multi-modal \emph{observation} composed of a vector of CICIoT2023 traffic features, a window of recent observations and actions, and (optionally, at evaluation time) the discrete predicted attack stage produced by the supervised stage detector. The simulator's latent dynamics are Markov in the full state $(s^{\text{stage}}_t, h_t)$, where $h_t$ is the history of observed stages and actions up to step $t$, but the defender never observes the true kill-chain stage $s^{\text{stage}}_t$ (that label is privileged simulator information available only to the oracle reference policy). The defender therefore solves a \textbf{Partially Observable MDP} (POMDP)~\cite{Sutton2018}, formalized as $(\mathcal{S}, A, \mathcal{O}, P, Z, R, \gamma)$, where $\mathcal{S}$ is the latent state space, $\mathcal{O}$ the observation space (feature vector plus histories), and $Z(o \mid s', a)$ the observation model induced by the split-aware feature realization engine. The severity of partial observability is governed by an \emph{observation-aliasing rate}~$\alpha$: with probability $\alpha$ the emitted feature row is drawn from a stage adjacent to the true one, so that $Z$ is a two-component mixture of the stage's own feature distribution and an adjacent stage's distribution (Eq.~\eqref{eq:aliasing_kernel}). As~$\alpha$ rises, distinct latent stages emit increasingly indistinguishable observations, sharpening the perception gap the policy must overcome. A POMDP-optimal policy acts on a belief $b_t(s) := \Pr(s_t = s \mid o_{1:t}, a_{1:t-1})$ over latent states, updated recursively via the Bayes filter after each observation $o_{t+1}$ under action $a_t$:
\begin{equation}\label{eq:belief_update_bg}
b_{t+1}(s') = \frac{Z(o_{t+1} \mid s', a_t) \sum_{s \in \mathcal{S}} P(s' \mid s, a_t)\, b_t(s)}{\sum_{s'' \in \mathcal{S}} Z(o_{t+1} \mid s'', a_t) \sum_{s \in \mathcal{S}} P(s'' \mid s, a_t)\, b_t(s)}.
\end{equation}
This dissertation approximates that belief with a fixed-length window of recent observations, so the trained policy is a history-conditioned approximation rather than a state-conditioned MDP policy. This perception gap (not control complexity) is the central difficulty of the task, and the oracle, which reads the latent stage directly, measures the value of closing it.

\subsection{Value Functions and Bellman Equations}\label{ssec:bellman}
To determine the quality of states and actions, RL uses value functions. The \textbf{state-value function}, $V^\pi(s)$, is the expected return from state $s$ while following policy $\pi$:
\begin{equation}\label{eq:state_value_function}
V^\pi(s) = \mathbb{E}_\pi \left[ \sum_{k=0}^{\infty} \gamma^k R_{t+k+1} \;\Big|\; S_t = s \right],
\end{equation}
where $R_{t+k+1}$ denotes the reward received at time $t+k+1$. The \textbf{action-value function} (or Q-function), $Q^\pi(s, a)$, is the expected return after taking action $a$ from state $s$ and then following policy $\pi$:
\begin{equation}\label{eq:action_value_function}
Q^\pi(s,a) = \mathbb{E}_\pi \left[ \sum_{k=0}^{\infty} \gamma^k R_{t+k+1} \;\Big|\; S_t = s, A_t = a \right].
\end{equation}
These functions adhere to the recursive relationships defined by the Bellman equations. The \textbf{Bellman optimality equation} for the Q-function is central to many RL algorithms and is expressed as:
\begin{equation}\label{eq:bellman_optimality}
Q^*(s, a) = \mathbb{E}_{s' \sim P(\cdot \mid s,a)} \left[ R(s,a,s') + \gamma \max_{a' \in A} Q^*(s', a') \right].
\end{equation}
Solving this equation yields the optimal Q-function, $Q^*(s, a)$, from which the optimal policy can be derived by selecting the action with the highest value in each state.

\subsection{Deep Reinforcement Learning Algorithms}\label{ssec:drl_algorithms}
For environments with large or continuous state spaces, like an IoT network, tabular methods are intractable. Deep Reinforcement Learning (DRL) overcomes this by using deep neural networks to approximate the value functions or policies \cite{Chen2021}. Three seminal DRL algorithms that represent the primary families of model-free RL are presented in the following.

\paragraph{Deep Q-Networks (DQN).}
DQN is a value-based, off-policy algorithm that uses an artificial neural network with weights $\theta$ to approximate the action-value function, $Q(s, a; \theta) \approx Q^*(s, a)$ \cite{Mnih2015}. The network is typically a multi-layer perceptron with two hidden layers of 64--256 units each and rectified linear unit (ReLU) activations, taking the state as input and outputting one Q-value per action. To stabilize learning, DQN introduces two critical mechanisms:
\begin{itemize}
    \item \textbf{Experience Replay:} Experiences $(s_t, a_t, r_t, s_{t+1})$ are stored in a large replay buffer. The network is trained on mini-batches randomly sampled from this buffer, which breaks temporal correlations in the data.
    \item \textbf{Fixed Target Network:} A separate, periodically updated target network with parameters $\theta^-$ is used to generate stable target values for the Bellman equation, preventing oscillations during training. The target network can be updated either \emph{hard} (copying the online network's parameters every $N$ steps) or \emph{soft} (polyak averaging, $\theta^- \leftarrow \eta_{\mathrm{targ}}\theta + (1-\eta_{\mathrm{targ}})\theta^-$ at every step); the original DQN uses hard updates, and soft updates are a common later refinement. The loss function is the Mean Squared Bellman Error:
    \begin{equation}\label{eq:dqn_loss}
    L(\theta) = \mathbb{E}_{(s,a,r,s') \sim \mathcal{D}} \left[ \left( \underbrace{r + \gamma \max_{a'} Q(s', a'; \theta^-)}_{\text{Target Q-value}} - \underbrace{Q(s, a; \theta)}_{\text{Predicted Q-value}} \right)^2 \right].
    \end{equation}
    where $\theta^-$ are the parameters of the fixed target network and $\mathcal{D}$ is the replay buffer.
\end{itemize}
Algorithm~\ref{alg:dqn} summarizes the DQN training loop.

\begin{algorithm}[!htbp]
\caption{Deep Q-Network (DQN) --- training loop \cite{Mnih2015}}
\label{alg:dqn}
\begin{algorithmic}
\REQUIRE replay buffer $\mathcal{D}$ with capacity $N$, minibatch size $B$, target update interval $C$, discount $\gamma$, exploration schedule $\epsilon$
\STATE Initialize online network $Q(s,a;\theta)$ with random weights
\STATE Initialize target network $Q(s,a;\theta^-) \leftarrow \theta$
\FOR{each episode}
    \STATE Observe initial state $s_0$
    \FOR{$t = 0, 1, 2, \ldots$}
        \STATE With probability $\epsilon$ select a random action $a_t$; otherwise $a_t \leftarrow \arg\max_a Q(s_t, a; \theta)$
        \STATE Execute $a_t$, observe reward $r_t$ and next state $s_{t+1}$
        \STATE Store transition $(s_t, a_t, r_t, s_{t+1})$ in $\mathcal{D}$
        \STATE Sample minibatch $\{(s_j, a_j, r_j, s'_j)\}_{j=1}^{B}$ from $\mathcal{D}$
        \STATE Compute targets $y_j \leftarrow r_j + \gamma \max_{a'} Q(s'_j, a'; \theta^-)$
        \STATE Update $\theta$ by gradient descent on $\frac{1}{B}\sum_j (y_j - Q(s_j, a_j; \theta))^2$
        \STATE Every $C$ steps (or softly each step) update $\theta^- \leftarrow \theta$ (or $\theta^- \leftarrow \eta_{\mathrm{targ}}\theta + (1-\eta_{\mathrm{targ}})\theta^-$)
    \ENDFOR
\ENDFOR
\end{algorithmic}
\end{algorithm}

\paragraph{Advantage Actor-Critic (A2C).}
A2C is a synchronous variant of the foundational Asynchronous Advantage Actor-Critic (A3C) algorithm \cite{Mnih2016}, and it is the algorithm that introduces the \textbf{actor-critic} architecture used by the subsequent methods. The agent maintains two networks: an \emph{actor} $\pi_\theta(a \mid s)$ that parameterizes the policy, and a \emph{critic} $V_\phi(s)$ that estimates the state-value function. The actor learns by policy-gradient ascent on the advantage, while the critic learns by temporal-difference regression. The \textbf{advantage function} $A^\pi(s, a) = Q^\pi(s, a) - V^\pi(s)$ measures how much better action $a$ is than the average action under $\pi$; in practice it is estimated with the temporal-difference residual $\hat{A}_t = r_t + \gamma V_\phi(s_{t+1}) - V_\phi(s_t)$. The combined A2C loss, with an entropy regularization term $H(\pi_\theta)$ weighted by $c_{\mathrm{ent}}$ to encourage exploration, is
\begin{equation}\label{eq:a2c_loss}
L_{\text{A2C}}(\theta, \phi) \;=\; \underbrace{-\log \pi_\theta(a_t \mid s_t)\,\hat{A}_t}_{\text{actor (policy gradient)}} \;+\; \underbrace{c_v\big(V_\phi(s_t) - \hat{R}_t\big)^2}_{\text{critic (value regression)}} \;-\; \underbrace{c_{\mathrm{ent}}\, H\big(\pi_\theta(\cdot \mid s_t)\big)}_{\text{entropy bonus}},
\end{equation}
where $c_v$ is the value-loss coefficient, $\hat{R}_t$ a return estimate, and $c_{\mathrm{ent}}$ the entropy coefficient. The return estimate $\hat{R}_t$ is algorithm-specific: for A2C it is the one-step bootstrap return $\hat{R}_t = r_t + \gamma V_\phi(s_{t+1})$ (Algorithm~\ref{alg:a2c}), whereas for PPO it is the GAE-based return $\hat{R}_t = \hat{A}_t + V_\phi(s_t)$ (Eq.~\eqref{eq:ppo_vf}, Algorithm~\ref{alg:ppo}). A2C typically employs multiple parallel workers that collect experience simultaneously; these experiences are then aggregated to compute a single synchronous gradient update for both actor and critic. While often faster to converge than PPO on simpler problems, it can be markedly less stable on standard benchmarks --- a general-literature characterization that is revisited in Chapter~\ref{cap:results}. Algorithm~\ref{alg:a2c} summarizes the A2C training loop.

\begin{algorithm}[!htbp]
\caption{Advantage Actor-Critic (A2C) --- synchronous training loop \cite{Mnih2016}}
\label{alg:a2c}
\begin{algorithmic}
\REQUIRE learning rate $\mathrm{lr}$, value coefficient $c_v$, entropy coefficient $c_{\mathrm{ent}}$, discount $\gamma$, $n$ parallel workers, rollout length $n_{\text{steps}}$
\STATE Initialize actor $\pi_\theta$ and critic $V_\phi$ with random weights
\FOR{each iteration}
    \FOR{each worker $k = 1, \ldots, n$ \textbf{in parallel}}
        \STATE Collect rollout $\{(s_t, a_t, r_t, s_{t+1})\}_{t=0}^{n_{\text{steps}}-1}$ using $\pi_\theta$
    \ENDFOR
    \STATE Aggregate transitions from all workers
    \FOR{$t = 0, 1, \ldots, n_{\text{steps}}-1$}
        \STATE Compute advantage $\hat{A}_t \leftarrow r_t + \gamma V_\phi(s_{t+1}) - V_\phi(s_t)$
        \STATE Compute return $\hat{R}_t \leftarrow r_t + \gamma V_\phi(s_{t+1})$
    \ENDFOR
    \STATE Update $\theta, \phi$ by gradient descent on $L_{\text{A2C}}$ (Eq.~\eqref{eq:a2c_loss})
\ENDFOR
\end{algorithmic}
\end{algorithm}

\paragraph{Proximal Policy Optimization (PPO).}
PPO is an on-policy actor-critic algorithm that builds directly on the A2C architecture (actor $\pi_\theta$ plus critic $V_\phi$) but constrains the size of policy updates to ensure greater training stability \cite{Schulman2017}. Its key innovation is a \emph{clipped surrogate objective} that prevents destructive large policy changes. Let $r_t(\theta)$ be the probability ratio between the new and old policies,
\begin{equation}\label{eq:ppo_ratio}
r_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{\text{old}}}(a_t \mid s_t)},
\end{equation}
and $\hat{A}_t$ the estimated advantage, computed with Generalized Advantage Estimation (GAE) \cite{Schulman2016}:
\begin{equation}\label{eq:gae}
\hat{A}_t \;=\; \sum_{l=0}^{T-t-1} (\gamma \lambda_{\text{GAE}})^{l}\, \delta_{t+l}, \qquad \delta_t \;=\; r_t + \gamma V_\phi(s_{t+1}) - V_\phi(s_t),
\end{equation}
where $\lambda_{\text{GAE}} \in [0,1]$ is the GAE bias-variance trade-off parameter. The PPO actor loss is the clipped surrogate
\begin{equation}\label{eq:ppo_clip}
L^{\mathrm{CLIP}}(\theta) = \hat{\mathbb{E}}_t \left[ \min \left( r_t(\theta)\hat{A}_t,\; \mathrm{clip}\!\left(r_t(\theta), 1-\epsilon, 1+\epsilon\right)\hat{A}_t \right) \right],
\end{equation}
where $\epsilon$ is a small hyperparameter that constrains the policy ratio to $[1-\epsilon, 1+\epsilon]$. The critic loss is the squared value error
\begin{equation}\label{eq:ppo_vf}
L^{\mathrm{VF}}(\phi) = \hat{\mathbb{E}}_t\big[(V_\phi(s_t) - \hat{R}_t)^2\big],
\end{equation}
and the full PPO objective combines actor, critic, and an entropy bonus:
\begin{equation}\label{eq:ppo_objective}
L^{\mathrm{PPO}}(\theta, \phi) \;=\; -L^{\mathrm{CLIP}}(\theta) \;+\; c_v\, L^{\mathrm{VF}}(\phi) \;-\; c_{\mathrm{ent}}\, H\big(\pi_\theta(\cdot \mid s_t)\big).
\end{equation}
This approach prevents destructive policy updates and is known for its reliability and performance. Algorithm~\ref{alg:ppo} summarizes the PPO training loop.

\begin{algorithm}[!htbp]
\caption{Proximal Policy Optimization (PPO) --- training loop \cite{Schulman2017}}
\label{alg:ppo}
\begin{algorithmic}
\REQUIRE clip range $\epsilon$, value coefficient $c_v$, entropy coefficient $c_{\mathrm{ent}}$, discount $\gamma$, GAE parameter $\lambda_{\text{GAE}}$, rollout length $n_{\text{steps}}$, epochs per update $K$, minibatch size $B$
\STATE Initialize actor $\pi_\theta$ and critic $V_\phi$ with random weights
\FOR{each iteration}
    \STATE Collect rollout $\{(s_t, a_t, r_t, s_{t+1})\}_{t=0}^{n_{\text{steps}}-1}$ using $\pi_{\theta_{\text{old}}}$
    \STATE Compute advantages $\hat{A}_t$ via GAE (Eq.~\eqref{eq:gae}) and returns $\hat{R}_t = \hat{A}_t + V_\phi(s_t)$
    \STATE Set $\theta_{\text{old}} \leftarrow \theta$
    \FOR{$k = 1, \ldots, K$}
        \STATE Sample minibatches of size $B$ from the rollout
        \STATE Update $\theta, \phi$ by gradient ascent on $-L^{\mathrm{PPO}}$ (Eq.~\eqref{eq:ppo_objective})
    \ENDFOR
\ENDFOR
\end{algorithmic}
\end{algorithm}

\section{Related Work in AI-Driven IoT Security}\label{sec:related_work_iot}
The application of artificial intelligence to IoT security is an active and rapidly evolving field of research. Early work focused on applying classical machine learning models to intrusion detection, which has since paved the way for more sophisticated, adaptive systems based on Deep Reinforcement Learning.

\subsection{Machine Learning Approaches for Intrusion Detection}
Early approaches to intelligent IoT security leveraged supervised and unsupervised machine learning (ML) for building Intrusion Detection Systems (IDS). Supervised models, such as Support Vector Machines and Random Forests, were trained on labeled datasets to classify network flows as either benign or malicious \cite{AlGaradi2020,DeMedeiros2023,Tawalbeh2020}. More recent work pushes this line toward deep and distributed learning: Okey et al.\ apply transfer learning with an optimized CNN to intrusion detection on cloud IoT devices \cite{Okey2023}, and later couple federated learning with CNN-GRU and LSTM-GRU ensembles to improve IoT intrusion detection without centralizing raw traffic \cite{Okey2024}. While effective at identifying known attack patterns, these models struggle with novel or zero-day attacks not seen during training, a limitation they share with traditional signature-based IDS \cite{Khraisat2019}. The KDD Cup 99 dataset and its successors (NSL-KDD, UNSW-NB15, Bot-IoT, CICIoT2023) have progressively provided more realistic evaluation grounds for IDS research \cite{Tavallaee2009,Koroniotis2019,Neto2023}. Furthermore, static ML classifiers are inherently passive: they identify threats without the capacity for automated, sequential defensive actions.

\subsection{The Shift to Active Defense with DRL}
The limitations of static ML models motivated a shift towards DRL to create autonomous agents capable of active, closed-loop cyber-defense \cite{Uprety2021,Yang2024,Gueriani2023}. The Cyber Kill Chain~\cite{Hutchins2011} and the MITRE ATT\&CK framework~\cite{MITRE2023} provide structured taxonomies that make the defender's decision frame explicit, enabling kill-chain-aligned reward functions like the one used in this dissertation. Several notable works have explored DRL-based IoT defense and provide the foundation upon which this dissertation builds.

Some research has focused on using RL for deception and intelligence gathering. The work of Guan et al.\ in HoneyIoT \cite{Guan2023} presents an adaptive high-interaction honeypot that uses Q-learning to learn an attacker's behavior and dynamically alter the services offered by a simulated IoT network (a configurable set of honeypot devices) to keep the attacker engaged and reveal their tactics. While this is a powerful application of RL, its primary purpose is reconnaissance, whereas the system presented in this dissertation is designed as a direct defense mechanism for a live network.

Other works have targeted specific layers of the IoT ecosystem. IoTWarden, proposed by Alam et al.\ \cite{Alam2024}, uses a DQN agent to mitigate attacks in trigger-action IoT platforms (e.g.\ IFTTT) by identifying and disabling malicious rules or ``applets'' in real time. This dissertation adopts the IoTWarden \emph{recommended-action mapping} (\textsc{benign}~$\to$~\textsc{observe}, \textsc{recon}~$\to$~\textsc{log}, \ldots, \textsc{impact}~$\to$~\textsc{isolate}) as a design choice for the environment's reward function, and treats IoTWarden as an inspiration rather than a head-to-head baseline: IoTWarden was evaluated on a different (synthetic, trigger-action) environment with a different action space, so direct numerical comparison is not methodologically sound. The headline numerical claim of this dissertation is therefore framed against the in-domain oracle ceiling described in Section~\ref{sec:baselines}, never against an external IoTWarden number. The same group has since extended this line with RESTRAIN \cite{Alam2025}, a multi-agent reinforcement-learning framework that profiles attack actions at runtime and coordinates several defender agents in a trigger-action IoT environment. RESTRAIN advances the IoTWarden agenda toward online, cooperative multi-agent defense and is the closest multi-agent analogue to the present work. Its contribution is orthogonal rather than competing: RESTRAIN tackles multi-agent coordination on a synthetic trigger-action platform, whereas this dissertation tackles \emph{per-flow partial observability} on real CICIoT2023 traffic. The two axes, cooperative coordination and single-agent belief under aliasing, are complementary. Integrating the partial-observability stressor studied here into a RESTRAIN-style multi-agent setting is a natural fusion left to future work (Section~\ref{sec:future_work}).

Hammar and Stadler~\cite{Hammar2022} model intrusion prevention as an optimal-stopping problem and train a hierarchical RL agent to decide when to escalate defensive actions, demonstrating that the decision-frame abstraction can simplify the policy learning problem. Caminero et al.~\cite{Caminero2019} use adversarial RL for zero-day-aware IDS, reporting a setting in which sequential decision-makers outperform passive classifiers for adaptive defense. The adversarial self-play paradigm (training a defender against a simultaneously evolving attacker) is explored by Elderman et al.~\cite{Elderman2017} in a cybersecurity simulation; this dissertation uses a fixed, reactive tug-of-war attacker in place of a jointly trained one, keeping the threat model fixed and reproducible while still making the defender--attacker interaction outcome-coupled: the attacker reacts to the defender's force, and its escalation pressure rises with proximity to the impact stage.

Tharewal et al.\ \cite{Tharewal2022} apply DRL to industrial IoT intrusion detection but treat the agent as a classifier rather than a sequential decision-maker. The most recent and most directly contrasting work in this vein is RL-IoTIDS \cite{Odeh2026}, which couples a DQN agent with a hybrid CNN-LSTM feature extractor to classify malicious traffic across the 33 CICIoT2023 attack categories, reporting higher F1 and lower false-alarm rates than SVM, RandomForest, and standalone deep-learning baselines. Although RL-IoTIDS is also a DRL system trained on CICIoT2023, it uses reinforcement learning to \emph{label} each flow (the reward rewards correct per-flow classification) so the learned policy is fundamentally a one-shot detector rather than a kill-chain controller. This is precisely the formulation this dissertation argues is insufficient under partial observability: where RL-IoTIDS optimizes per-flow detection accuracy, the present work optimizes sustained, well-timed defensive \emph{control} over a temporal window. Chapter~\ref{cap:results} shows that the latter prevents attacks a classifier-style policy cannot, with an advantage that does not track the classifier's per-class labeling accuracy. The comprehensive surveys by Kheddar et al.~\cite{Kheddar2024} and Yang et al.~\cite{Yang2024} confirm that DQN, PPO, and A2C are the most widely evaluated algorithms for network intrusion response, validating the algorithm selection in this dissertation. This dissertation addresses a more fundamental challenge by operating at the network layer: it analyzes features derived from raw traffic to defend against the broad range of network-level attacks (DDoS, DoS, Spoofing) prevalent in CICIoT2023, and it structures the policy as a kill-chain-aware sequential decision-maker under genuine partial observability.

The key differentiators are (i) training and evaluation on real feature rows from a large-scale, real-capture dataset (CICIoT2023) rather than wholly synthetic features, sampled into a simulated kill-chain trajectory; (ii) a partially-observable formulation in which an observation-aliasing rate~$\alpha$ controls stage ambiguity, under which windowed PPO stays robust while a tuned RandomForest baseline (RF-Acting) degrades; (iii) an explicit oracle-ceiling measurement instrument that quantifies the value of perfect stage detection, with head-to-head reward comparisons against deployable baselines; (iv) a held-out attack-class feature-injection evaluation that probes distribution shift without leaking reserved classes into training; and (v) a Gymnasium-compatible~\cite{Gymnasium2023} simulator that enables reproducible re-evaluation by third parties without re-running the full training pipeline.

While previous works have successfully applied DRL to specific aspects of IoT security, a gap remains for a comprehensive, network-level defense system that is simultaneously robust under controlled partial observability, grounded in contemporary IoT traffic features, network-layer focused, benchmarked and stress-tested, and reproducible by construction. This dissertation directly addresses these gaps by designing, implementing, and evaluating a complete framework that integrates these critical components, thereby advancing the development of resilient, intelligent systems capable of defending the vast and ever-expanding IoT landscape. Specifically, the framework combines a supervised stage detector and a reactive, proximity-coupled tug-of-war attacker with a DRL agent in a closed loop from kill-chain dynamics to autonomous action under partial observability induced by an observation-aliasing rate~$\alpha$ --- a regime in which windowed PPO remains stable as~$\alpha$ rises while a tuned RandomForest baseline degrades; it is validated on the large-scale and contemporary CICIoT2023 dataset, with documented kill-chain projections and a split-aware protocol that prevents train/test leakage and supports held-out attack-class feature-injection evaluation; it is designed to defend against a broad range of fundamental network attacks by analyzing traffic-flow features; it provides a thorough empirical comparison of modern value-based (DQN) and actor-critic (PPO, A2C) algorithms against three trivial baselines, a deployable supervised-plus-rule baseline (RF-Acting), and an oracle reference --- with non-overlapping bootstrap confidence intervals as the statistical-separation criterion, and with robustness probed across rising observation aliasing and held-out attack-class feature injection; and every reported figure is accompanied by a provenance manifest pinning its input data and the exact code revision that produced it, so the full result set can be regenerated end-to-end from a clean repository state.
