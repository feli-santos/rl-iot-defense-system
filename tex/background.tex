\section{The Cyber Kill Chain as a Defender's Decision Frame}\label{sec:kill_chain}
The \textbf{Cyber Kill Chain} \cite{Hutchins2011,Mavroeidis2023} is a conceptual model that decomposes a sustained intrusion into a sequence of progressively more compromising stages. Originally formulated by industrial threat-intelligence practitioners~\cite{Hutchins2011} and refined by the academic community, it organises adversary behaviour as an ordered chain in which earlier stages prepare for the success of later stages and where defender opportunity costs grow monotonically with stage progression. Interrupting an attack at \textsc{recon} is far cheaper than interrupting it at \textsc{impact}.

Following the formulation adopted in this dissertation (and consistent with the IoTWarden recommended-action mapping \cite{Alam2024}), traffic on an IoT network is projected onto a five-stage kill chain:

\begin{enumerate}
    \item \textbf{\textsc{benign}} --- routine, non-malicious traffic. The defender's correct posture is observational.
    \item \textbf{\textsc{recon}} --- the adversary scans, fingerprints, or otherwise enumerates the network and its assets. Behaviour is malicious but the network is not yet compromised; the defender's correct posture is to log and continue monitoring.
    \item \textbf{\textsc{access}} --- the adversary establishes an initial foothold (e.g.\ exploit-driven authentication bypass, brute-force, command injection). The defender should restrict the implicated traffic and prepare to escalate.
    \item \textbf{\textsc{maneuver}} --- the adversary performs lateral movement, privilege escalation, or other in-network manipulation to position for a final action. The defender should block.
    \item \textbf{\textsc{impact}} --- the adversary's terminal action: data exfiltration, denial-of-service, ransomware detonation. The defender's last opportunity to prevent loss is to isolate the affected segment.
\end{enumerate}

The kill chain is more than narrative scaffolding: it provides a discrete decision frame in which (i) the attacker's evolving state is summarised by a single ordered variable and (ii) the defender's action menu can be aligned to that variable through a recommended-action mapping (\textsc{benign}~$\to$~\textsc{observe}, \textsc{recon}~$\to$~\textsc{log}, \textsc{access}~$\to$~\textsc{restrict}, \textsc{maneuver}~$\to$~\textsc{block}, \textsc{impact}~$\to$~\textsc{isolate}). This alignment is the basis of the stage-action proportionality reward used in Section~\ref{sec:rl_environment}, and it is what makes the rule-based recommended-action policy a meaningful upper bound (Section~\ref{sec:baselines_taxonomy}).

\section{Reinforcement Learning for Autonomous Systems}\label{sec:rl_concepts}
Reinforcement Learning (RL) is a computational paradigm focused on goal-directed learning from interaction. An intelligent agent learns to make optimal decisions not by being shown labeled examples, but by exploring an environment and discovering which sequences of actions yield the greatest cumulative reward \cite{Sutton2018}. This learning process is formalised through the mathematical framework of Markov Decision Processes (MDPs).

\subsection{Markov Decision Processes}\label{ssec:mdp}
An MDP provides a formal model for sequential decision-making under uncertainty. The core principle is the \textbf{Markov Property}, which asserts that the current state provides all necessary information to make an optimal decision, rendering the history of prior states irrelevant \cite{Sutton2018}. An MDP is defined as a five-tuple $(S, A, P, R, \gamma)$:
\begin{itemize}
    \item $\boldsymbol{S}$: A finite set of states, representing all possible configurations of the environment. In this dissertation the underlying simulator carries a \emph{latent} Markov state that includes the true kill-chain stage and the stage/action histories. Crucially, the defender does not observe this latent state directly: it receives only a multi-modal \emph{observation} composed of a vector of CICIoT2023 traffic features, a window of recent observations and actions, and (optionally, at evaluation time) the discrete predicted attack stage produced by the supervised stage detector. The distinction between the latent state and the defender-facing observation is made precise below.
    \item $\boldsymbol{A}$: A finite set of actions. For this work, $A$ is the five-action defender menu derived from the kill chain in Section~\ref{sec:kill_chain}: $A = \{\textsc{observe}, \textsc{log}, \textsc{restrict}, \textsc{block}, \textsc{isolate}\}$, ordered by escalating defensive force and operational disruption.
    \item $\boldsymbol{P}$: The state transition probability function, $P(s' \mid s, a) = \Pr(S_{t+1}=s' \mid S_t=s, A_t=a)$, defining the dynamics of the environment.
    \item $\boldsymbol{R}$: The reward function, $R(s, a, s')$, which provides the immediate numerical feedback for transitioning from $s$ to $s'$ via action $a$. The full as-built reward used in this dissertation is detailed in Section~\ref{sec:rl_environment}.
    \item $\boldsymbol{\gamma}$: The discount factor ($0 \leq \gamma \leq 1$), which prioritises immediate rewards over future ones.
\end{itemize}
The agent's objective is to learn a \textbf{policy}, $\pi(a \mid s)$, which maps states to a probability distribution over actions, to maximise the expected discounted return.

\paragraph{From MDP to POMDP: the defender's perception gap.} The simulator's latent dynamics are Markov in the full state $(s^{\text{stage}}_t, h_t)$, but the defender never observes the true kill-chain stage $s^{\text{stage}}_t$ --- that label is privileged simulator information available only to the oracle reference policy. The defender therefore solves a \textbf{Partially Observable MDP} (POMDP), formalised as $(\mathcal{S}, A, \mathcal{O}, P, Z, R, \gamma)$, where $\mathcal{S}$ is the latent state space, $\mathcal{O}$ the observation space (feature vector plus histories), and $Z(o \mid s', a)$ the observation model induced by the split-aware feature realization engine. The severity of partial observability is governed by an \emph{observation-aliasing rate}~$\alpha$: as~$\alpha$ rises, distinct latent stages emit increasingly indistinguishable observations, sharpening the perception gap the policy must overcome. A POMDP-optimal policy acts on a belief over latent states; this dissertation approximates that belief with a fixed-length window of recent observations, so the trained policy is a history-conditioned approximation rather than a state-conditioned MDP policy. This perception gap --- not control complexity --- is the central difficulty of the task, and the oracle, which reads the latent stage directly, measures the value of closing it.

\subsection{Value Functions and Bellman Equations}\label{ssec:bellman}
To determine the quality of states and actions, RL uses value functions. The \textbf{state-value function}, $V^\pi(s)$, is the expected return from state $s$ while following policy $\pi$:
\begin{equation}\label{eq:state_value_function}
V^\pi(s) = \mathbb{E}_\pi \left[ \sum_{k=0}^{\infty} \gamma^k R_{t+k+1} \;\Big|\; S_t = s \right]
\end{equation}
The \textbf{action-value function} (or Q-function), $Q^\pi(s, a)$, is the expected return after taking action $a$ from state $s$ and then following policy $\pi$:
\begin{equation}\label{eq:action_value_function}
Q^\pi(s,a) = \mathbb{E}_\pi \left[ \sum_{k=0}^{\infty} \gamma^k R_{t+k+1} \;\Big|\; S_t = s, A_t = a \right]
\end{equation}
These functions adhere to the recursive relationships defined by the Bellman equations. The \textbf{Bellman optimality equation} for the Q-function is central to many RL algorithms and is expressed as:
\begin{equation}\label{eq:bellman_optimality}
Q^*(s, a) = \mathbb{E}_{s' \sim P(\cdot \mid s,a)} \left[ R(s,a,s') + \gamma \max_{a' \in A} Q^*(s', a') \right]
\end{equation}
Solving this equation yields the optimal Q-function, $Q^*(s, a)$, from which the optimal policy can be derived by selecting the action with the highest value in each state.

\subsection{Deep Reinforcement Learning Algorithms}\label{ssec:drl_algorithms}
For environments with large or continuous state spaces, like an IoT network, tabular methods are intractable. Deep Reinforcement Learning (DRL) overcomes this by using deep neural networks to approximate the value functions or policies \cite{Chen2021}. This dissertation implements and benchmarks three seminal DRL algorithms that represent the primary families of model-free RL.

\paragraph{Deep Q-Networks (DQN).}
DQN is a value-based, off-policy algorithm that uses a neural network to approximate the action-value function, $Q(s, a; \theta) \approx Q^*(s, a)$ \cite{Mnih2015}. To stabilise learning, DQN introduces two critical mechanisms:
\begin{itemize}
    \item \textbf{Experience Replay:} Experiences $(s_t, a_t, r_t, s_{t+1})$ are stored in a large replay buffer. The network is trained on mini-batches randomly sampled from this buffer, which breaks temporal correlations in the data.
    \item \textbf{Fixed Target Network:} A separate, periodically updated target network is used to generate stable target values for the Bellman equation, preventing oscillations during training. The loss function is the Mean Squared Bellman Error:
    \begin{equation}\label{eq:dqn_loss}
    L(\theta) = \mathbb{E}_{(s,a,r,s') \sim \mathcal{D}} \left[ \left( \underbrace{r + \gamma \max_{a'} Q(s', a'; \theta^-)}_{\text{Target Q-value}} - \underbrace{Q(s, a; \theta)}_{\text{Predicted Q-value}} \right)^2 \right]
    \end{equation}
    where $\theta^-$ are the parameters of the fixed target network and $\mathcal{D}$ is the replay buffer.
\end{itemize}

\paragraph{Proximal Policy Optimization (PPO).}
PPO is a state-of-the-art on-policy actor-critic algorithm that directly optimises a parameterised policy (the actor) while using a value function (the critic) to reduce variance \cite{Schulman2017}. Its key innovation is a clipped surrogate objective function that constrains the size of policy updates, ensuring greater training stability:
\begin{equation}\label{eq:ppo_clip}
L^{\mathrm{CLIP}}(\theta) = \hat{\mathbb{E}}_t \left[ \min \left( r_t(\theta)\hat{A}_t,\; \mathrm{clip}\!\left(r_t(\theta), 1-\epsilon, 1+\epsilon\right)\hat{A}_t \right) \right]
\end{equation}
where $r_t(\theta)$ is the probability ratio between the new and old policies, $\hat{A}_t$ is the estimated advantage, and $\epsilon$ is a hyperparameter that constrains the policy change. This approach prevents destructive policy updates and is known for its reliability and performance.

\paragraph{Advantage Actor-Critic (A2C).}
A2C is a synchronous variant of the foundational Asynchronous Advantage Actor-Critic (A3C) algorithm \cite{Mnih2016}. Like PPO, it is an actor-critic method, but it uses a simpler, unconstrained policy update mechanism. It typically employs multiple parallel workers to collect experience simultaneously; these experiences are then aggregated to compute a single stable gradient update for both the actor (policy) and the critic (value function). While often faster to converge than PPO on simpler problems, it can be markedly less stable --- a fragility that, as Chapter~\ref{cap:results} reports, becomes salient under sparse reward, where only PPO trains reliably.

All three algorithms are implemented in this dissertation using Stable~Baselines3~\cite{Raffin2021} \texttt{MlpPolicy}, a multi-layer perceptron that processes the flat \texttt{Box} observation space (dimension~290) exposed by the custom IoT environment described in Section~\ref{sec:rl_environment}.

\paragraph{Rationale for the DQN/PPO/A2C selection.}
The three algorithms were selected to span the primary families of model-free DRL while keeping computational cost manageable on CPU-only hardware. DQN serves as the \textbf{off-policy value-based baseline}: its experience-replay buffer is sample-efficient and well-studied as a reference point for discrete-action problems. PPO represents the \textbf{on-policy actor-critic mainstream}: it is the \emph{de facto} standard for policy-gradient benchmarking due to its stability and resistance to catastrophic policy updates \cite{Schulman2017}. A2C is included as a \textbf{faster-converging on-policy alternative}: its synchronous update mechanism typically converges in fewer wall-clock steps on simpler environments, at the cost of higher variance relative to PPO \cite{Mnih2016}. This trio is recommended by the Stable~Baselines3 benchmarking guide~\cite{Raffin2021} for discrete-action environments with moderate state complexity and has been used as a canonical comparison set in several DRL-for-IDS studies \cite{Kheddar2024,Yang2024}. Continuous-action and model-based algorithms (e.g., SAC, TD3, Dreamer) are excluded because the five-action discrete defender menu does not require them and would introduce additional hyperparameter complexity without methodological benefit. The reward function used across all three algorithms is a heuristic, kill-chain-aligned shaping reward inspired by reward-shaping principles~\cite{Ng1999} (recommended-action proportionality incentives, capped de-escalation bonuses, and terminal accounting). It is \emph{not} claimed to be a policy-invariant potential-based transformation in the strict sense of \citeonline{Ng1999}: it mixes action- and stage-dependent costs, guardrails, and per-episode caps that have no associated potential function. The design consequences of this reward are not assumed away but probed directly: the headline experiments contrast this proportionality-shaped \emph{coupled} reward against a sparse \emph{outcome-only} reward (Section~\ref{sec:rl_environment}). This comparison addresses a natural concern --- that a proportionality reward simply hands the agent a privileged classification target --- by showing that the reinforcement-learning advantage survives the removal of that shaping for the policy-gradient agent that remains trainable under sparse reward~\cite{Amodei2016}. The constrained-MDP framework~\cite{Altman1999} informs the optional false-positive penalty.

\section{Deployable Baselines and the Role of an Oracle Reference}\label{sec:baselines_taxonomy}
A defining methodological choice of this work is to evaluate the trained DRL agents not only against \emph{trivial} baselines (random, always-\textsc{observe}, always-\textsc{block}) but also against two stronger references that bracket the achievable performance under the kill-chain decision frame:

\begin{itemize}
    \item \textbf{RF-Acting (deployable supervised + rule).} A composite policy that uses a supervised RandomForest classifier (trained in the stage-detection phase) to predict the current attack stage from the observed feature vector, then maps the predicted stage to an action via the recommended-action mapping. RF-Acting is fully deployable: it consumes only what a real defender can observe and produces a defensive action at every step.
    \item \textbf{Recommended-Action rule (oracle reference, \emph{not} a competing baseline).} An identical action-selection rule that, instead of consuming a learned classifier's output, reads the \emph{true} attack stage directly from the simulator's privileged information. This oracle is therefore a measurement instrument that quantifies the value of perfect stage detection under the chosen reward function. Because it does not run on observable inputs and cannot be deployed, it is reported as an \emph{upper bound} on what any deployable policy could achieve under the recommended-action mapping, never as a method this work claims to outperform.
\end{itemize}

The trained DRL agents are deployable in the same sense as RF-Acting, but strictly \emph{detector-free}: the benchmarked DRL policies observe only a vector of CICIoT2023 traffic features (plus a short history of recent observations and actions) and produce an action; they do \emph{not} consume the predicted stage. Only RF-Acting consumes a stage classifier's output. The DRL agents are scored against both deployable baselines and against the oracle ceiling, which Section~\ref{cap:results} reports for all policies.

\section{Related Work in AI-Driven IoT Security}\label{sec:related_work_iot}
The application of artificial intelligence to IoT security is an active and rapidly evolving field of research. Early work focused on applying classical machine learning models to intrusion detection, which has since paved the way for more sophisticated, adaptive systems based on Deep Reinforcement Learning.

\subsection{Machine Learning Approaches for Intrusion Detection}
Early approaches to intelligent IoT security leveraged supervised and unsupervised machine learning for building Intrusion Detection Systems (IDS). Supervised models, such as Support Vector Machines and Random Forests, were trained on labeled datasets to classify network flows as either benign or malicious \cite{AlGaradi2020,Ibitoye2021}. While effective at identifying known attack patterns, these models struggle with novel or \textbf{zero-day attacks} not seen during training, a limitation they share with traditional signature-based IDS \cite{Khraisat2019}. The KDD Cup 99 dataset and its successors (NSL-KDD, UNSW-NB15, Bot-IoT, CICIoT2023) have progressively provided more realistic evaluation grounds for IDS research \cite{Tavallaee2009,Koroniotis2019,Neto2023}. Furthermore, static ML classifiers are inherently passive: they identify threats without the capacity for automated, sequential defensive actions --- a limitation this dissertation addresses directly by composing the supervised classifier with a recommended-action rule (RF-Acting) and using it as a deployable baseline against which the DRL agents are scored.

\subsection{The Shift to Active Defense with DRL}
The limitations of static ML models motivated a shift towards DRL to create autonomous agents capable of active, closed-loop cyber-defense \cite{Uprety2021,Yang2024,Gueriani2023}. The Cyber Kill Chain~\cite{Hutchins2011} and the MITRE ATT\&CK framework~\cite{MITRE2023} provide structured taxonomies that make the defender's decision frame explicit, enabling kill-chain-aligned reward functions like the one used in this dissertation. Several notable works have explored DRL-based IoT defense and provide the foundation upon which this dissertation builds.

Some research has focused on using RL for deception and intelligence gathering. The work of Guan et al.\ in \textbf{HoneyIoT} \cite{Guan2023} presents an adaptive high-interaction honeypot that uses RL to learn an attacker's behavior and dynamically alter its services to keep the attacker engaged and reveal their tactics. While this is a powerful application of RL, its primary purpose is reconnaissance, whereas the system presented in this dissertation is designed as a direct defense mechanism for a live network.

Other works have targeted specific layers of the IoT ecosystem. \textbf{IoTWarden}, proposed by Alam et al.\ \cite{Alam2024}, uses a DQN agent to mitigate attacks in trigger-action IoT platforms (e.g.\ IFTTT) by identifying and disabling malicious rules or ``applets'' in real time. This dissertation adopts the IoTWarden \emph{recommended-action mapping} (\textsc{benign}~$\to$~\textsc{observe}, \textsc{recon}~$\to$~\textsc{log}, \ldots, \textsc{impact}~$\to$~\textsc{isolate}) as a design choice for the environment's reward function, and treats IoTWarden as an inspiration rather than a head-to-head baseline: IoTWarden was evaluated on a different (synthetic, trigger-action) environment with a different action space, so direct numerical comparison is not methodologically sound. The headline numerical claim of this dissertation is therefore framed against the in-domain oracle ceiling described in Section~\ref{sec:baselines_taxonomy}, never against an external IoTWarden number. The same group has since extended this line with \textbf{RESTRAIN} \cite{Alam2025}, a multi-agent reinforcement-learning framework that profiles attack actions at runtime and coordinates several defender agents in a trigger-action IoT environment. RESTRAIN advances the IoTWarden agenda toward online, cooperative multi-agent defense and is the closest multi-agent analogue to the present work. Its contribution is orthogonal rather than competing: RESTRAIN tackles multi-agent coordination on a synthetic trigger-action platform, whereas this dissertation tackles \emph{per-flow partial observability} on real CICIoT2023 traffic. The two axes --- cooperative coordination and single-agent belief under aliasing --- are complementary; integrating the partial-observability stressor studied here into a RESTRAIN-style multi-agent setting is a natural fusion left to future work (Section~\ref{sec:future_work}).

Hammar and Stadler~\cite{Hammar2022} model intrusion prevention as an optimal-stopping problem and train a hierarchical RL agent to decide when to escalate defensive actions, demonstrating that the decision-frame abstraction can simplify the policy learning problem. Tang et al.~\cite{Tang2020} apply DRL to SDN-based IoT intrusion response, and Caminero et al.~\cite{Caminero2019} use adversarial RL for zero-day-aware IDS, both reporting settings in which sequential decision-makers outperform passive classifiers for adaptive defense. The adversarial self-play paradigm --- training a defender against a simultaneously evolving attacker --- is explored by Elderman et al.~\cite{Elderman2017} in a cybersecurity simulation; this dissertation uses a fixed, reactive tug-of-war attacker in place of a jointly trained one, keeping the threat model fixed and reproducible while still making the defender--attacker interaction outcome-coupled: the attacker reacts to the defender's force, and its escalation pressure rises with proximity to the impact stage.

Tharewal et al.\ \cite{Tharewal2022} apply DRL to industrial IoT intrusion detection but treat the agent as a classifier rather than a sequential decision-maker. The most recent and most directly contrasting work in this vein is \textbf{RL-IoTIDS} \cite{Odeh2026}, which couples a DQN agent with a hybrid CNN-LSTM feature extractor to classify malicious traffic across the 33 CICIoT2023 attack categories, reporting higher F1 and lower false-alarm rates than SVM, RandomForest, and standalone deep-learning baselines. Although RL-IoTIDS is also a DRL system trained on CICIoT2023, it uses reinforcement learning to \emph{label} each flow --- the reward rewards correct per-flow classification --- so the learned policy is fundamentally a one-shot detector rather than a kill-chain controller. This is precisely the formulation this dissertation argues is insufficient under partial observability: where RL-IoTIDS optimises per-flow detection accuracy, the present work optimises sustained, well-timed defensive \emph{control} over a temporal window, and shows (Chapter~\ref{cap:results}) that the latter prevents attacks a classifier-style policy cannot, with an advantage that does not track the classifier's per-class labelling accuracy. The comprehensive surveys by Kheddar et al.~\cite{Kheddar2024} and Yang et al.~\cite{Yang2024} confirm that DQN, PPO, and A2C are the most widely evaluated algorithms for network intrusion response, validating the algorithm selection in this dissertation. This dissertation addresses a more fundamental challenge by operating at the \textbf{network layer}: it analyses features derived from raw traffic to defend against the broad range of network-level attacks (DDoS, DoS, Spoofing) prevalent in CICIoT2023, and it structures the policy as a kill-chain-aware sequential decision-maker under genuine partial observability.

The key differentiators are (i) training and evaluation on real feature rows from a large-scale, real-capture dataset (CICIoT2023) rather than wholly synthetic features, sampled into a simulated kill-chain trajectory; (ii) a partially-observable formulation in which an observation-aliasing rate~$\alpha$ controls stage ambiguity, under which windowed PPO stays robust while a tuned RandomForest baseline (RF-Acting) degrades; (iii) an explicit oracle-ceiling measurement instrument that quantifies the value of perfect stage detection, with head-to-head reward comparisons against deployable baselines; (iv) a held-out attack-class feature-injection evaluation that probes distribution shift without leaking reserved classes into training; and (v) a Gymnasium-compatible~\cite{Gymnasium2023} simulator that enables reproducible re-evaluation by third parties without re-running the full training pipeline.

\subsection{Positioning the Dissertation: Bridging the Research Gap}
While previous works have successfully applied DRL to specific aspects of IoT security, a gap remains for a comprehensive, network-level defense system that is simultaneously:
\begin{itemize}
    \item \textbf{Robust under Controlled Partial Observability:} combining a supervised stage detector and a reactive, proximity-coupled tug-of-war attacker with a DRL agent in a closed loop from kill-chain dynamics to autonomous action under partial observability induced by an observation-aliasing rate~$\alpha$ --- a regime in which windowed PPO remains stable as~$\alpha$ rises while a tuned RandomForest baseline degrades.
    \item \textbf{Grounded in Contemporary IoT Traffic Features:} validated on the large-scale and contemporary \textbf{CICIoT2023 dataset}, with documented kill-chain projections and a split-aware protocol that prevents train/test leakage and supports held-out attack-class feature-injection evaluation.
    \item \textbf{Network-Layer Focused:} designed to defend against a broad range of fundamental network attacks by analysing traffic-flow features.
    \item \textbf{Benchmarked and Stress-Tested:} providing a thorough empirical comparison of modern value-based (DQN) and actor-critic (PPO, A2C) algorithms against three trivial baselines, a deployable supervised-plus-rule baseline (RF-Acting), and an oracle reference --- with non-overlapping bootstrap confidence intervals as the statistical-separation criterion, and with robustness probed across rising observation aliasing and held-out attack-class feature injection.
    \item \textbf{Reproducible by Construction:} every reported figure is accompanied by a provenance manifest pinning its input data and the exact code revision that produced it, so the full result set can be regenerated end-to-end from a clean repository state.
\end{itemize}
This dissertation directly addresses these gaps by designing, implementing, and evaluating a complete framework that integrates these critical components, thereby advancing the development of resilient, intelligent systems capable of defending the vast and ever-expanding IoT landscape.
