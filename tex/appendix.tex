\chapter{Reproducibility Protocol and Verification Recipe}\label{app:repro}
% ====================================================================

This appendix documents the reproducibility protocol that underpins every numerical claim in this dissertation, following a model-card-style template for machine-learning artifacts \cite{Mitchell2019}. Each figure, table, and benchmark number is pinned to its inputs and the producing Git commit by a manifest, and a lightweight verification harness rebuilds the chain end-to-end on a fresh checkout.

\section{Per-Stage Manifest Pattern}\label{app:manifest_pattern}
Every component of the framework emits one or more \texttt{manifest.json} files under \texttt{docs/results/} that record (a) a content hash of every input artifact (data splits, trained models, scaler, episode roll-outs, upstream manifests), (b) the producing Git commit (\texttt{git\_sha}), and (c) the producing-script invocation (\texttt{produced\_by}). Each manifest also records the hash of every output artifact (figure, summary JSON) so that a downstream component can pin an upstream output by hash, not by filename alone. The artifact inventory is summarized in Table~\ref{tab:manifest_inventory}.

\section{Verification Harness}\label{app:r1}
The harness \texttt{scripts/reproducibility\_smoke.py} walks every committed \texttt{manifest.json} file under \texttt{docs/results/} and verifies, for every recorded input artifact, that its on-disk content hash \emph{right now} matches the hash recorded by the manifest that consumed it. A mismatch flags a figure or summary that is no longer reproducible-by-hash from the inputs on disk. Inputs that are gitignored and absent on a fresh clone (large feature arrays \texttt{features.npy}/\texttt{stages.npy} and split-index files derived from the raw CICIoT2023 dataset) are reported as skipped rather than failed. On a fresh checkout the harness passes with no unexplained mismatches.

\section{Verification Recipe (Fresh-Checkout Reproduction)}\label{app:recipe}
On a fresh checkout, the empirical record can be re-verified end-to-end without retraining any model:

\begin{verbatim}
git clone <repo-url> rl-iot-defense-system
cd rl-iot-defense-system
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest -q                             # expect: 462 passed
python -m scripts.reproducibility_smoke
# expect: VERDICT PASS (no unexplained hash mismatches)
\end{verbatim}

The dissertation PDF is compiled via a local container image (Podman, with Docker as a fallback; no host-side \LaTeX{} installation required):

\begin{verbatim}
# Compile tex/main.pdf (auto-builds the image if absent):
make thesis

# Alternatively, use the standalone script from the repo root
# (auto-detects and prefers Podman):
bash tex/build.sh
\end{verbatim}

A full re-train from scratch (preserving the reproducibility contract) is also supported via \texttt{make}:

\begin{verbatim}
make dataset                 # CICIoT2023 splits; needs raw data
make detector                # supervised stage detector + F11
make blue-team-sweep         # train DQN/PPO/A2C; fixed 5M-step
                             # budget, no early stopping (seeded)
make benchmark               # held-out alpha-curve benchmark
make ablation                # reward-coupling, OOD, sensitivity
\end{verbatim}

After a full re-train the \texttt{manifest.json} files are re-emitted with new input hashes corresponding to the freshly trained checkpoints; the harness then verifies the new chain end-to-end.

\section{Hardware and Environment}\label{app:hardware}
All experiments reported in this dissertation were run on a CPU-only commodity workstation. No GPU is required: the tuned random-forest stage detector and the three DRL agents all train within minutes-to-hours on commodity CPU, and the $5\times5$ escalation attacker is closed-form and requires no training. The DRL agents are trained CPU-only; the random-forest baseline uses scikit-learn's default multi-core fit (\texttt{n\_jobs}=$-1$). Software environment: Python 3.9 (CI-verified), PyTorch (CPU build), scikit-learn, Stable~Baselines3, Gymnasium. Each learned agent is trained for a fixed $5{,}000{,}000$-step budget with no early stopping, under a fully seeded pipeline that makes both training and checkpoint selection bit-reproducible from the seed. The full evaluation chain completes in a few hours on this commodity CPU, dominated by the reward-coupling sweep.

\chapter{Hyperparameters per Algorithm}\label{app:hparams}
% ====================================================================

The per-algorithm training hyperparameters for PPO, A2C, and DQN are listed in Table~\ref{tab:hparams}, one column per algorithm. Each configuration was chosen by a small grid search rather than left at library defaults, so that every learned agent is trained under settings appropriate to the sparse outcome-reward regime; the same values are used across all \NumSeeds{} seeds (\texttt{seed} $\in \{0, 1, \ldots, 9\}$). A dash marks a hyperparameter that does not apply to a given algorithm family, so the on-policy and off-policy knobs sit side by side in a single table. PPO retains the standard configuration; A2C uses a substantially longer rollout ($n_{\text{steps}} = 256$ rather than the default $5$) to give the on-policy estimator enough horizon for the long credit-assignment delay, and DQN uses a larger replay buffer and slower target updates to stabilize the off-policy bootstrap.

The rollout length, GAE $\lambda_{\text{GAE}}$, entropy and value coefficients, and epoch count are specific to the actor-critic methods (PPO/A2C), while the replay buffer, learning-starts threshold, target-update interval, and exploration schedule are specific to off-policy DQN.}}

\paragraph{Network architecture.} All three algorithms use the Stable Baselines3 \texttt{MlpPolicy}, a multi-layer perceptron with two hidden layers of 64 units each and ReLU activations, shared across policy and value networks for PPO/A2C and used as the Q-network for DQN. The same architecture is used across all seeds and algorithms to isolate the learning-rule comparison from network-capacity effects.

The reward-coupling and out-of-distribution evaluations re-use these hyperparameters unchanged; only the environment contract (reward mode, observation aliasing, held-out classes) is perturbed.
